# Decisions

## 2026-07-31: 랜딩의 주인공을 진단에서 제작·운영 실행으로 바꾼다

- 결정: 타깃을 `이미 마케팅 중이지만 방향이 흩어진 사업`으로 정의하고, 필요한 콘텐츠의 우선순위를 정한 뒤 제작·운영까지 맡는 역할을 랜딩의 핵심 약속으로 둔다. 상담은 진입 과정이며 CTA는 `마케팅 상담하기`로 통일한다.
- 이유: 기존 랜딩은 1시간 진단과 다음 달 우선순위를 최종 상품처럼 보여 오로라의 실제 수익 역할인 통합 실행 범위를 충분히 전달하지 못했다.
- 영향: `index.html`, `style.css`, `script.js`, 카피·제품 문서와 프로필 메시지가 같은 포지셔닝을 사용한다.

## 2026-07-31: HTML data 속성을 추적의 단일 원본으로 사용한다

- 결정: 모든 추적 링크는 `data-track`과 고유 id를 사용하고, 카카오 클릭의 위치와 주요 CTA 여부를 data 속성으로 기록한다. `/interview/`는 `/interview`로 정규화하며 Meta `Contact`는 광고 경로의 카카오 외부 링크 클릭으로만 정의한다.
- 이유: ID별 하드코딩은 새 CTA에서 누락·중복을 만들었고, 기존 동적 noscript Pixel은 PageView를 중복시킬 수 있었으며 슬래시 경로는 404였다.
- 영향: `analytics.js`, `vercel.json`, `scripts/check-site.mjs`, `README.md`, `prd.md`, `docs/TRD.md`를 함께 관리하고 클라이언트에서 `Lead`를 보내지 않는다.

## 2026-07-26: 랜딩의 주된 약속을 다음 한 달의 우선순위로 바꾼다

- 결정: 이미 마케팅을 운영 중인 전문직과 소규모 사업자를 대상으로, 1시간 진단 미팅에서 다음 한 달의 우선순위·수정 기준·역할 구분을 정하는 제안으로 랜딩을 개편하고 실제 열람 10초를 `engaged_10s`로 측정한다.
- 이유: 첫 문장 교정만으로는 오로라가 진단하는 전체 범위와 미팅 뒤 남는 결과가 충분히 보이지 않았고, 광고 클릭 이후의 실제 열람 여부도 구분할 필요가 있었다.
- 영향: 첫 문장 시연은 판단 증거로 내려가며 `index.html`, `style.css`, `analytics.js`, 캐시 버전과 제품·디자인·추적 문서를 함께 갱신한다.

## 2026-07-21: 대표 글 보기 경로를 WordPress 블로그로 통일한다

- 결정: 히어로의 Brunch 보조 CTA를 제거하고 `blog.aurorasound.kr`로 연결하며, 히어로와 푸터 클릭을 `click_wordpress_blog`로 함께 측정한다.
- 이유: 자체 도메인 콘텐츠 자산으로 방문을 모으고 랜딩과 블로그 사이의 이동 경로를 일관되게 유지하기 위해서다.
- 영향: 오가닉 랜딩 방문자는 WordPress 글로 이동하고, 광고 경로에서는 기존처럼 보조 CTA가 숨겨진다.

## 2026-07-21: 운영 추적과 문의 이벤트를 분리한다

- 결정: GA4·Meta Pixel은 운영 도메인에서만 실행하고, 광고 경로의 카카오 링크 클릭은 Meta `Contact`로 기록한다.
- 이유: localhost PageView와 실제 방문이 섞였고 링크 클릭을 실제 `Lead`로 집계해 전환 의미가 부풀려졌다.
- 영향: 운영 데이터 오염을 막고 `CTA 클릭 → 실제 문의 → 유효 문의`를 서로 다른 단계로 측정한다.

## 2026-05-04: Project Operating Guide 적용

결정:

- 기존 `README.md`와 `prd.md`는 운영 원본으로 유지한다.

- 이 프로젝트는 정적 사이트라 저장소 루트 파일이 공개 배포 표면에 섞일 수 있다.
- `/`와 `/interview`가 같은 랜딩을 보여주되 추적 맥락만 분리하는 정책을 유지해야 한다.

## 2026-05-21: 랜딩 검색 기본 파일 보강

결정:

- 대표 랜딩에 canonical, Open Graph URL/image, Twitter card, 구조화 데이터를 추가한다.
- `robots.txt`와 `sitemap.xml`을 공개 배포 표면에 추가한다.
- `/interview`는 광고 추적용 동일 랜딩 경로이므로 사이트맵에는 대표 URL `/`만 싣는다.
- `privacy.html`은 `noindex` 페이지라 사이트맵에서 제외한다.
- 대표 랜딩 푸터에서 워드프레스 블로그로 직접 이동하는 링크를 추가해 검색로봇과 사용자가 블로그를 더 쉽게 발견하게 한다.

이유:

- 랜딩은 이미 제목과 설명은 갖고 있었지만 검색 엔진에 대표 URL과 사이트맵을 명시하는 기본 파일이 없었다.
- 광고 경로와 오가닉 대표 경로를 검색 색인에서 혼동시키지 않기 위해 canonical은 대표 URL로 둔다.
